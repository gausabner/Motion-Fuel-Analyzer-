# Power BI build guide: from the PBIP project to the `.pbix` and `.pbit`

The semantic model and the four report pages are delivered as a **Power BI Project** (`GreenBasket_Agri.pbip`):
TMDL for the model, PBIR for the report. Both were generated by `build_pbip.py` and validated before release:

- The model was deserialised and re-serialised by Microsoft's own Tabular Object Model in Power BI mode
  (22 tables, 79 measures, 34 relationships, 3 roles).
- All 58 report files pass the official Microsoft JSON schemas.
- Every visual field reference resolves to a model object.

What could **not** be done in the build environment, because Power BI Desktop runs only on Windows:

- opening the project;
- refreshing data;
- saving the `.pbix`;
- exporting the `.pbit`;
- capturing screenshots and timings.

This guide is the critical path for those steps. Allow about 60–90 minutes for one person. Do it on the team's
Windows machine **before** writing the final screenshots into the report.

---

## 0. Prerequisites

| Item | Version / note |
|---|---|
| Power BI Desktop | A current release (2025 or later). Open **File › Options and settings › Options › Preview features**. If these options are listed, tick them and restart: *Power BI Project (.pbip) save option*, *Store semantic model using TMDL format*, *Store reports using enhanced metadata format (PBIR)*. Newer releases have them on by default. |
| PostgreSQL | 16.x (14+ works). Not needed for CSV mode (step 3b). |
| psql / pg_restore | On PATH. They come with the PostgreSQL installer. |
| Optional tools | DAX Studio 3.x (timings, VertiPaq Analyzer) and Tabular Editor 2 (free). |

## 1. Restore the warehouse (about 5 minutes)

```bat
cd abi820s-green-basket-bi
psql -U postgres -f 02_sql\00_create_database.sql
pg_restore -U postgres -d green_basket_dw --no-owner 05_backup\green_basket_dw_pg16_warehouse.backup
psql -U postgres -d green_basket_dw -c "GRANT USAGE ON SCHEMA mart TO gb_pbi_reader; GRANT SELECT ON ALL TABLES IN SCHEMA mart TO gb_pbi_reader;"
psql -U postgres -d green_basket_dw -c "ALTER ROLE gb_pbi_reader PASSWORD '<choose-a-password>';"
```

- `00_create_database.sql` creates the database and the two least-privilege roles. The restore needs them for its grants.
- The backup leaves out the `stg` staging schema to keep it small, so do **not** run `10_security_grants.sql` on a
  restored copy: it grants on `stg`. The one-line `GRANT` above is all the Power BI reader needs. (These exact
  commands were tested: restore exit code 0, 22 mart views, the check query below matches.)
- Alternative: rebuild everything from source in about 3 minutes with
  `python run_all.py --dsn postgresql://postgres:<pw>@localhost:5432/green_basket_dw --skip-generate`.

Check the restore:

```sql
SELECT count(*), sum(net_revenue_nad) FROM mart.fact_sales;
-- expected: 302903 | 2110889914.70
```

## 2. Open the project

1. Copy `04_powerbi\` to a short local path, e.g. `C:\GreenBasket\04_powerbi\`. Long OneDrive paths break PBIP.
2. Double-click `GreenBasket_Agri.pbip`.
3. If Desktop reports an unsupported format, see **Fallback A**.

## 3. Point the model at the data

### 3a. PostgreSQL mode (recommended: shows the real ELT lineage)

1. **Home › Transform data › Edit parameters**:
   - `PgServer` = `localhost:5432`
   - `PgDatabase` = `green_basket_dw`
   - `SourceMode` = `PostgreSQL`
2. When prompted for credentials, choose **Database**, user `gb_pbi_reader`, and the password set in step 1. If the
   local server has no TLS certificate, accept the *unencrypted connection* prompt (local lab only; see report §3.8).
3. Click **Home › Refresh**.

### 3b. CSV mode (no PostgreSQL available)

1. Set `SourceMode` = `CSV`.
2. Set `CsvFolder` = the full folder path of `data_csv\` **with a trailing backslash**, for example
   `C:\GreenBasket\04_powerbi\data_csv\`. The files are the same mart views, exported as gzip CSV.
3. Refresh.

How to read these numbers:

- **Zone totals do not add up to the executive total.** The four zones sum to N$ 451,947,728. The difference of

## 5. Interactivity to add in Desktop (about 20 minutes)

These are built by hand. They do not depend on any generated file.

1. **Drill-through page "Farm Detail"**
   1. Add a new page and put `Farm[Farm]` in *Drill through*.
   2. Add cards for Net Revenue, Yield (t/ha), Direct Cost per Tonne and Gross Margin %.
   3. Add a line chart of Net Revenue by `Date[Year Month]`.
   4. Add a table of `Crop Cycle` showing crop, season, yield, plan and status.
   5. Leave *Keep all filters* on.
2. **Report-page tooltip "Revenue tip"**
   1. Set page size to *Tooltip*.
   2. Add Net Revenue YoY %, Gross Margin % and Export Share %.
   3. Assign it to the trend line on the Executive page (**Format › Tooltips › Report page**).
3. **Bookmarks and buttons**
   1. Create a bookmark "Executive view" (slicers reset, FY2026).
   2. Create a bookmark "Analyst view" (selection pane shows the Metric Selector visual).
   3. Add two buttons that toggle them.
4. **Field parameter**
   1. Add a slicer on `'Metric Selector'[Metric]`.
   2. Add a line chart with that field on the Y axis and `Date[Year Month]` on the X axis.
   3. Users then switch between 6 measures without new visuals.
5. **Sync slicers**: sync Fiscal year and Management zone across pages 1, 2 and 4 (**View › Sync slicers**).
6. **Conditional formatting** (always icon + colour, never colour alone):
   - Farm scorecard *YoY %*: icon set ▲ ▼.
   - Yield matrix *vs plan*: icons and font colour (good #006300 / bad #d03b3b from the theme).
   - Data bars on Net revenue.
7. **Edit interactions**: on page 1, set the KPI cards to *None* for cross-highlight from the crop bar chart. This
   keeps the headline stable while users explore.
8. **Accessibility check**:
   - Every visual already has alt text and a title.
   - Set the tab order under **View › Selection › Tab order**: title → slicers → cards → charts.
   - Verify that *Show as a table* works on each chart.

## 6. Incremental refresh policy (Sales)

The model already has the `RangeStart` and `RangeEnd` datetime parameters. The `Sales` query filters on integer
date keys, and that filter folds to SQL.

1. In Table view, right-click **Sales** and choose **Incremental refresh**.
2. Archive data starting **5 years** before refresh date.
3. Incrementally refresh data starting **10 days** before refresh date.
4. Leave *Get the latest data in real time* off.
5. Optionally, *Only refresh complete days*.
6. Click **Apply**.

The policy takes effect only after publishing to a Pro, PPU or Premium/Fabric workspace. In Desktop the
parameters simply bound the import window (2020-01-01 to 2027-01-01).

## 7. Performance evidence (for §3.7)

1. **Performance Analyzer**
   1. Open **View › Performance analyzer › Start recording**.
   2. On each page, click **Refresh visuals** three times.
   3. Export the JSON to `06_report\evidence\pa_<page>.json`.
   4. Record the median *DAX query* ms of the slowest visual per page.
2. **DAX Studio**
   1. Connect to the open model, enable **Server Timings**, and choose **Clear cache** before each run.
   2. Time these three measures:
      - `EVALUATE SUMMARIZECOLUMNS('Date'[Year Month], "x", [Net Revenue FYTD PY])`
      - `... [Closing Stock (t)]` by `Farm[Farm]`
      - `... [Stock Cover (days)]` by `Farm[Farm]`
   3. Write down total ms, Storage Engine ms, Formula Engine ms and SE queries.
3. **VertiPaq Analyzer** (**DAX Studio › Advanced › View Metrics**):
   1. Export the `.vpax`.
   2. Record the total model size and the five largest columns.
   3. Compare them with `06_report/evidence/perf_model.md`, which is the build-time estimate.
4. **Optimisation already designed in.** Show one before/after in Desktop:
   - Temporarily import `dw.fact_sales` (all 24 columns, including the text `invoice_no`, the `sales_line_key`
     surrogate, the stored `gross_margin_nad` and audit columns) instead of `mart.fact_sales`. The mart version
     has 14 columns, keeps an integer `invoice_id` and leaves margin to a measure.
   - Compare the VertiPaq model size. The build-time proxy predicts about 16.0 MB → 10.8 MB.
   - Then revert.

## Fallbacks

The fallbacks are in order of preference. Each is self-contained.

**A. Desktop cannot open the PBIP** (for example an older release without TMDL or PBIR support)

1. Create a blank report.
2. **File › Save as › Power BI project**, then close Desktop.
3. Replace the new project's `*.SemanticModel\definition\` folder with this one.
4. Replace `*.Report\definition\` with this one.
5. Re-open the project.

If only the model loads, rebuild the pages from the mock-ups using fallback C's measures.

**B. TMDL view script**

1. Open a blank report and go to **TMDL view**.
2. Paste `GreenBasket_model_script.tmdl` (a single `createOrReplace` script holding the whole model) and click **Apply**.
3. Edit the parameters as in step 3 and refresh.

**C. Manual build**

1. **Get data › PostgreSQL**, then select the 20 `mart.*` views and rename them to the friendly names in the row-count table.
2. Create the 34 relationships from the ERD in report §3.2. Single direction, many-to-one. Role-playing dates are
   inactive except the primary one.
3. Paste the measures from `measures.dax`.

**D. CSV mode without PostgreSQL**: see step 3b. All figures in this guide are identical in CSV mode.
