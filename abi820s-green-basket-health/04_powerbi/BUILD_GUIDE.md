# Power BI build guide: from the PBIP project to the `.pbix` and `.pbit`

The semantic model and the report are delivered as a **Power BI Project** (`GBHS_Health.pbip`): TMDL for the model,
PBIR for the report. Both were generated by `build_pbip.py` and validated before release:

- **Model.** Microsoft's Tabular Object Model, in Power BI mode, deserialised the model and re-serialised it to TMDL.
  It holds 32 tables, 108 measures, 38 relationships (37 active, 1 inactive), 4 security roles and the
  incremental-refresh policy.
- **Report.** All 83 report files pass the official Microsoft JSON schemas. There are 6 pages: 4 report pages, 1
  drill-through page and 1 tooltip page.
- **References.** Every field used by a visual, the drill-through filter and every tooltip binding resolves to a
  model object.
- **DAX.** A static check passed on all 113 DAX expressions: references, functions, brackets, unused variables, and
  no measure inside a boolean filter argument.

What could **not** be done in the build environment, because Power BI Desktop runs only on Windows:

- opening the project;
- refreshing data;
- executing the DAX;
- saving the `.pbix`;
- exporting the `.pbit`;
- capturing screenshots and timings.

This guide is the critical path for those steps. Allow **60–90 minutes for one person**. Do it on the team's Windows
machine **before** the final screenshots go into the report.

Every number you are asked to check below was computed independently in SQL by `expected_values.py`, which mirrors
each measure's DAX. The full list is in `expected_values.md`.

## 0. Prerequisites

| Item | Version / note |
|---|---|
| Power BI Desktop | A current release (2025 or later). Under **File › Options and settings › Options › Preview features**, if these options are listed, tick them and restart: *Power BI Project (.pbip) save option*, *Store semantic model using TMDL format*, *Store reports using enhanced metadata format (PBIR)*. Newer releases have them on by default. |
| PostgreSQL | 16.x (14+ works). Not needed in CSV mode (step 3b). |
| psql / pg_restore | On PATH; they come with the PostgreSQL installer. |
| Optional tools | DAX Studio 3.x (timings, VertiPaq Analyzer) and Tabular Editor 2 (free). |

## 1. Restore the warehouse (about 5 minutes)

```bat
cd abi820s-green-basket-health
psql -U postgres -f 02_sql\00_create_database.sql
pg_restore -U postgres -d gbhs_health_dw --no-owner 05_backup\gbhs_health_dw_pg16_warehouse.backup
psql -U postgres -d gbhs_health_dw -c "GRANT USAGE ON SCHEMA mart TO gbhs_pbi_reader; GRANT SELECT ON ALL TABLES IN SCHEMA mart TO gbhs_pbi_reader;"
psql -U postgres -d gbhs_health_dw -c "ALTER ROLE gbhs_pbi_reader PASSWORD '<choose-a-password>';"
```

- `00_create_database.sql` creates the database and the two least-privilege roles. The restore needs both roles for
  its grants.
- The backup leaves out the `stg` landing schema to keep it small. Do **not** run `10_security_grants.sql` on a
  restored copy, because it grants on `stg`. The one-line `GRANT` above is all the Power BI reader needs.
- Alternative: rebuild everything from the raw extracts in about 5 minutes with
  `python run_all.py --dsn postgresql://postgres:<pw>@localhost:5432/gbhs_health_dw --skip-generate`.

Check the restore:

```sql
SELECT (SELECT count(*) FROM mart.v_fact_encounter)  AS attendances,   -- 560557
       (SELECT count(*) FROM mart.v_fact_admission)  AS spells,        -- 135629
       (SELECT sum(cases_total) FROM mart.v_fact_surveillance) AS idsr_cases,   -- 121390
       (SELECT sum(population) FROM mart.v_fact_population WHERE is_census_count) AS census_2023;  -- 3022401
```

## 2. Open the project

1. Copy `04_powerbi\` to a short local path, e.g. `C:\GBHS\04_powerbi\`. Long OneDrive paths break PBIP.
2. Double-click `GBHS_Health.pbip`.
3. If Desktop reports an unsupported format, use **Fallback A** at the end of this guide.

## 3. Point the model at the data

### 3a. PostgreSQL mode (recommended: shows the real ELT lineage)

1. Open **Home › Transform data › Edit parameters** and set:
   - `PgServer` = `localhost:5432`
   - `PgDatabase` = `gbhs_health_dw`
   - `SourceMode` = `PostgreSQL`
2. When prompted for credentials, choose **Database**, user `gbhs_pbi_reader`, and the password from step 1. If the
   local server has no TLS certificate, accept the *unencrypted connection* prompt. This is acceptable for a local
   lab only; see report §3.8.
3. Click **Home › Refresh**. It takes about 1–2 minutes.

### 3b. CSV mode (no PostgreSQL available)

1. Set `SourceMode` = `CSV`.
2. Set `CsvFolder` to the full path of `data_csv\` **with a trailing backslash**, e.g.
   `C:\GBHS\04_powerbi\data_csv\`. The files are the same mart views exported as gzip CSV by `export_fallbacks.py`.
3. Refresh. Every figure in this guide is identical in CSV mode.

How to read the results:

- **The five facility managers add up exactly to the executive totals** (81,612 and 14,571), because every
  attendance and IDSR return belongs to exactly one facility.
- **An unmapped user sees nothing.** Dynamic RLS fails closed.
- **The Surveillance Partner (OLS) role behaves differently.** The tables `Attendance`, `Admission`, `Patient`,
  `Readmission Deciles`, `Readmission Drivers` and `Security User Facility` disappear from the field list. Visuals
  that use them show *"Something's wrong with one or more fields"*; that is the designed behaviour, so take a
  screenshot. The Disease Surveillance page works normally.
- **Each user belongs to one role only.** Power BI rejects a user who is in an RLS role and an OLS role at the
  same time, so never assign one person to both.
- `ceo@gbhs.example` has a home-facility row in `sec.user_facility_access` for audit purposes only. The CEO is a
  member of the **Executive** role, which has no filter.

After publishing:

1. Open **Semantic model › Security**.
2. Add the Entra ID groups to the roles, e.g. `GBHS-FacilityManagers`, `GBHS-Executives`, `MoHSS-Surveillance`.
3. Re-test with **Test as role**.

## 5. Interactivity: check the generated features and add the manual ones (about 25 minutes)

**Generated, so only check them:**

1. **Drill-through.** On the Executive Overview scorecard, right-click a facility and choose
   **Drill through › Facility Detail**.
   - The page title shows the facility.
   - The *Back* button returns you to the scorecard. In Desktop, use Ctrl+click.
   - If the button shows no arrow icon, delete it and use **Insert › Buttons › Back**.
2. **Report-page tooltip.** Hover a bar in *Bed occupancy by hospital*; the *KPI Tooltip* page should appear.
   - If the default tooltip appears instead, open the *KPI Tooltip* page, go to **Format page › Page information**
     and set **Allow use as tooltip** to On.
   - Then, on the bar chart, go to **Format › Properties › Tooltips** and set **Type** = *Report page* and
     **Page** = *KPI Tooltip*.
3. **Edit interactions.** On page 1, the occupancy bar chart and the scorecard do not filter the six KPI cards.
   This keeps the headline stable. Check under **Format › Edit interactions**.
4. **Sync slicers.** *Calendar year*, *Facility* and *Management zone* are in sync groups. Check under
   **View › Sync slicers**.
5. **Drill-down.** In the *Ward utilisation* matrix on page 2, use the expand arrows to go Region › Facility › Ward.

**Built by hand:**

6. **Field parameter.** The `Metric Selector` table is already in the model. On the Patient Flow page:
   1. Add a slicer on `'Metric Selector'[Metric]` and set it to single select.
   2. Add a line chart with `Metric` on the Y-axis and `Date[Year Month]` on the X-axis.
   3. Users can now switch between 9 KPIs without new visuals.
7. **KPI reference labels.** The mock-ups show these.
   1. Convert the six cards on pages 1 and 3 to the new **Card** visual.
   2. Add these reference labels:
      - *Seen Within Target Change (pp)* and *ED Target Status* under *Seen within triage target*;
      - *Occupancy Status* under *Bed occupancy*;
      - *ED Attendances YTD PY* under *ED attendances YTD*.
8. **Bookmarks and buttons.**
   1. Create a bookmark "Current year" (Calendar year = 2026, all facilities).
   2. Create a bookmark "Malaria season" (Date › Is Malaria Season = True on pages 1–2).
   3. Add two buttons that apply them.
9. **Conditional formatting.** Always use an icon plus colour, never colour alone.
   1. On the scorecard *Within target* column, add icons using rules ≥ 80 % (good) and < 80 % (bad), with the
      theme colours good #006300 and bad #D03B3B.
   2. Do the same on *LWBS* (rule ≤ 3 %) and on *Occupancy* (rule ≤ 85 %).
10. **Accessibility check.**
    - Alt text and tab order are generated for every visual. Verify them under **View › Selection › Tab order**.
    - Check that *Show as a table* works on each chart.
    - Check the contrast of the theme colours against white; the palette passed the dataviz validator.

## 6. Incremental refresh (Attendance)

The policy is **already in the model**. It keeps 5 years, refreshes the last 10 days, and uses the
`RangeStart`/`RangeEnd` filter on the integer `arrival_date_key`, which folds to SQL. To check it:

1. In Table view, right-click **Attendance** and choose **Incremental refresh**. It should show *Archive 5 years*
   and *Incrementally refresh 10 days*. Take a screenshot.
2. The policy takes effect only after publishing to a Pro, PPU or Premium/Fabric workspace. In Desktop the
   parameters simply bound the import window (2022-01-01 to 2027-01-01).
3. The build-time benchmark shows the effect: one incremental partition reads 3,214 rows instead of 560,557
   (`06_report/evidence/perf_model.md`).

## 7. Performance evidence (for §3.7)

1. **Performance Analyzer.**
   1. Open **View › Performance analyzer** and click **Start recording**.
   2. On each page, click **Refresh visuals** three times.
   3. Export the JSON to `06_report\evidence\pa_<page>.json`.
   4. For each page, note the median *DAX query* ms of the slowest visual.
2. **DAX Studio.** Connect to the open model, enable **Server Timings**, and run **Clear cache** before each query.
   - `EVALUATE SUMMARIZECOLUMNS('Date'[Year Month], "x", [Seen Within Target % PY])` (time intelligence)
   - `EVALUATE SUMMARIZECOLUMNS('Facility'[Facility], 'Date'[Epi Year], "inc", [Malaria Incidence per 100k])`
     (iterator over epi years)
   - `EVALUATE SUMMARIZECOLUMNS('Date'[Year Month], "adc", [Average Daily Census], "last", [Occupied Beds (Latest Day)])`
     (semi-additive)
   - For each query, record total ms, Storage Engine ms, Formula Engine ms and the number of SE queries.
3. **VertiPaq Analyzer** (**DAX Studio › Advanced › View Metrics**).
   1. Export the `.vpax`.
   2. Record the total model size and the five largest columns.
   3. Compare them with `06_report/evidence/perf_model.md`, which is the build-time estimate.
4. **Show one optimisation before and after.**
   1. Temporarily import `dw.fact_encounter` instead of `mart.v_fact_encounter`. The `dw` version has 21 columns,
      including the 563k-distinct `encounter_id` and `encounter_key`, `age_years` and the audit columns.
   2. Compare the VertiPaq size. The build-time proxy predicts about 23.0 MB for the naive model and 12.5 MB for
      the optimised one.
   3. Revert.

## Fallbacks

The fallbacks are listed in order of preference. Each one is self-contained.

**A. Desktop cannot open the PBIP** (for example an older release without TMDL or PBIR support)

1. Create a blank report.
2. **File › Save as › Power BI project**, then close Desktop.
3. Replace the new project's `*.SemanticModel\definition\` folder with this one.
4. Replace `*.Report\definition\` with this one.
5. Re-open the project.

If only the model loads, rebuild the pages from the mock-ups.

**B. TMDL view script**

1. Open a blank report and go to **TMDL view**.
2. Paste `GBHS_model_script.tmdl`, a single `createOrReplace` script holding the whole model, and click **Apply**.
3. Edit the parameters as in step 3 and refresh.

**C. Manual build**

1. **Get data › PostgreSQL**, select the 30 `mart.*` objects and rename them to the table names in step 3.
2. Create the 38 relationships from the ERD in report §3.2. All are single direction and many-to-one;
   `Admission[Discharge Date Key]` is inactive.
3. Paste the measures from `measures.dax` and create the four roles listed at the end of that file.

**D. CSV mode without PostgreSQL**: see step 3b.
